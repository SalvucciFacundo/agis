## Approaches

### Fork 1 — Skill creation trigger ("from experience")

1. **Session-close extraction** — extend the close flow: after the summarizer, a skill-curator pass asks the LLM whether the session produced a reusable procedure worth saving.
   - Pros: reuses proven close pipeline; deterministic point; matches "after complex tasks".
   - Cons: close latency grows (second bounded LLM call).
   - Effort: Medium
2. **Cadence nudge** — second curator-style nudge every N turns during the session.
   - Pros: symmetric with observation nudges.
   - Cons: mid-stream interruptions; noisy; skills rarely form per-N-turns.
   - Effort: Medium
3. **Explicit only** (`/skill save`) + user file imports.
   - Pros: zero surprise, cheapest.
   - Cons: does not satisfy spec's "created by the agent".
   - Effort: Low

**Recommendation: 1 (+3 free)** — close-time extraction satisfies the spec; file-drop imports come free with the loader. Kill switch via config.

### Fork 2 — Persona evolution mechanics

1. **Derived overlay** (GAIA-style) — SOUL.md stays static; evolution is a computed overlay layer assembled from user-model/observations, inserted after SOUL.md. `freeze` disables the layer; `reset` clears the underlying observations' participation.
   - Pros: honors "seed, not a cage" without ever rewriting user files; reversible by construction; cheap.
   - Cons: evolution quality depends on observation curation prompts.
   - Effort: Medium
2. **LLM rewrites SOUL.md** periodically.
   - Pros: literal "evolution".
   - Cons: mutating the identity file is destructive, hard to review, fights the never-overwrite principle.
   - Effort: High

**Recommendation: 1** — evolution as derived state, never file mutation.

### Fork 3 — Registry location

Default `$AGIS_HOME/.atl/skill-registry.md` (instance-scoped like SOUL.md), path configurable. Project-local `.atl/` stays reserved for tooling caches (this repo proves they churn). Divergence note recorded in design.
